# Studio template contract

This project is a starting scaffold for an AI-built product, not a finished
demo. Adapt the Studio layout in place and finish the real user flow end to
end. Rendering the shipped examples is not completion.

## Layout

- `app/` — Next.js App Router (`layout.tsx`, `page.tsx`, `globals.css`,
  `api/upload/route.ts` for signed reference-upload URLs).
- `layouts/studio.tsx` — the Studio screen. Read `layouts/AGENTS.md` before
  changing its structure.
- `components/studio/` — Studio building blocks. Read
  `components/studio/AGENTS.md` before composing UI.
- `components/ui/` — shadcn primitives (Base UI). Add more with
  `pnpm dlx shadcn@latest add <name>`; do not hand-roll a second UI system.
- `generation/` — the Higgsfield platform layer: model catalog
  (`catalog/models/*.ts`, one file per model, barrel regenerated by
  `scripts/sync-models.mjs`), platform client, server actions, zustand stores.
  Browser code never sees the platform key.
- `lib/generations/` — the generation service (create, finalize, reconcile,
  cancel, delete), storage drivers and webhook tokens. Dependencies are passed
  in, so it runs in tests against Postgres and the fake Higgsfield.
- `lib/studio/` — the `useRuns` controller (history from Postgres via
  `/api/generations`), zustand projects and uploads.

## Runtime boundaries — preserve these

- `generation/actions.ts`, `app/api/**` and `auth.ts` are the server boundaries.
  The platform key is `HF_API_KEY` in the server environment
  (`lib/server/generation-env.ts`); there is no per-user key. Every action and
  route checks the session itself, and every query filters by `user_id`.
- Generate and Cancel both reach the platform (`submitGeneration`,
  `cancelGeneration`). Do not replace cancel with "stop polling".
- Models come from `generation/catalog`. To add one, drop a file in
  `generation/catalog/models/` (or `pnpm dlx shadcn@latest add
  higgsfield-ai/app-templates/<model>`); the dev server regenerates the barrel.
  Never hand-edit `generation/catalog/models.generated.ts`.
- Preserve every installed model when adapting a product. `studio` installs the
  full catalog; use `studio-bare` or a model allowlist only when the user explicitly
  requests a smaller catalog. Keep models visible when their live API behavior
  is unverified and report that limitation. Verify every installed model appears
  in its image/video picker after adaptation.
- Reference uploads request a signed URL through `app/api/upload/route.ts`
  using the saved platform key. The browser PUTs the file with every returned
  upload header and no credentials. Record the public URL only after success;
  never log signed URLs. No separate storage token is needed.
- Generation history lives in Postgres (`generations` table) behind the
  `useRuns` interface. Projects are still browser-local
  (`lib/studio/projects.ts`) until they move to Postgres.
- The justified gallery is virtualized by rows. Never unmount loaded media
  because scroll velocity is high; never filter out failed terminal runs the
  user already saw generating.
- Never touch `window`, `document`, `navigator`, or storage during SSR render
  or at module scope. Client components are marked `"use client"`.

## Definition of done

- Copy, presets, metadata, navigation and errors describe the user's product
  rather than this scaffold.
- Every `/presets/placeholder-*.svg` and mock template in
  `components/studio/template-picker.tsx` is replaced with real, on-brand
  media at the component's aspect ratio, then the placeholders are deleted.
- Every visible control performs its named action or is removed. No inert
  buttons, empty menus or `onClick={() => {}}`.
- Dark theme only. No app header, no theme toggle, no `dark:` classes.
- `pnpm typecheck` and `pnpm build` pass without weakening strict TypeScript
  (`any`, `@ts-ignore`, `@ts-expect-error` are not fixes).

## Verification scenarios

- Generate from prompt only and from image/video references; switch surface
  (image/video) and model; change a setting in the settings dialog.
- Signed out (Generate goes to sign-in and keeps the prompt), content-filter
  block, failure and cancel each stay visible as feed tiles or dock errors.
- Empty history, populated history, a project with a few generations, project
  rename/delete.
- Fast scrolling keeps loaded media; keyboard focus and reduced motion work;
  narrow viewports do not introduce a second app shell.
